#### What is AlgoPulse
* **`AlgoPulse` is an algorithmic trading execution backend developed in `C++` (supports Windows/Linux) focus on Chinese A-Stock. Users can build upon this basic framework and existing algorithms to improve or develop their own intraday trading strategies (T0 or pair trading).**
    - `✓` Implements typical TWAP/VWAP algorithm execution examples and supports extensible intraday trading strategies (momentum/T0/event-driven...) and market-making strategies.
    - `✓` Currently integrates real-time market data from the internet, enabling complete algorithmic trading strategy simulation and backtesting.
    - `✓` Uses H5 format for data storage: daily static information of securities, Level 1 market quote, daily bar data, and minute-level bar data.
    - `✓` As a backend program, the frontend can communicate with it via TCP connections and defined protobuf message structures.
    - `✘` For live trading, users need to implement related classes (e.g., QuoteFeedLive and OrderBook) based on their broker's API.

* Unlike general quantitative backtesting frameworks that focus on daily or minute-level trading and backtesting, this framework is entirely oriented towards tick-level market quote snapshot for trading and backtesting. Therefore, it does not provide complete multi-day account backtesting curve analysis but instead:
    - `✓` For algorithmic trading: focuses on slippage backtesting analysis (e.g., VWAP slippage, TWAP slippage, arrivePrice slippage).
    - `✓` For intraday trading: focuses on profit-loss ratios, win rates, and excess returns.
    - `✓` Signals generated by intraday strategies can be converted into algorithmic orders for execution (via the AlgoPlacer class), synthesizing an Order to report back to the strategy, avoiding the need for the strategy to handle multiple child orders.
    - `✓` Backtesting a full-market algorithm or strategy will group stocks into multiple subtasks for multithreaded backtesting and then aggregate the results.

### Algorithmic Trading Execution: Tick-Driven with Timer Integration
* For some stocks with poor liquidity, ticks may only occur every few seconds or minutes. Relying solely on market depth quote to drive algorithm execution may be insufficient. Therefore, this project uses C++ coroutines and integrates timers as a supplement.
* For a given algorithmic order with a specified duration, it is generally divided into multiple second-segments (slices), and execution progress tracks TWAP, VWAP, or POV.

        for (auto& slicer : slicers) {
            curSlicerIndex = slicer.index;
            co_await executeSlicer(slicer);
        }

   Meanwhile, during onMarketDepth, based on order book changes or predictive signals, decisions can be made within slices to use take or make order actions:

       onMarketDepth(const MarketDepth* newMd) {
            algoPerf.performanceSummay(newMd);
            executeSignal(newMd, m_md.get()); // quick act on predict LOB change if possible
        }

   If `executeSignal` is not defined, each slice will be executed under coroutine scheduling based on execution progress.
   During backtesting, when encountering timers, the backtesting coroutine will suspend and resume execution when the replayed market data reaches the corresponding time.

### Intraday Trading Strategy Example (Event-Driven)

* See `shot/shotTrader` for strategy logic:
    
    - Within a specified continuous window (N * 3-second market data intervals), if there is a rapid rise greater than 2% followed by a pullback, record the highest price H and lowest price L within the window.
    - After an interval of M (a few or several minutes), if the price rises again and breaks the previous high, this serves as a confirmation signal to buy.
    - If a new low or high occurs within the continuous window, reset H and L.
